# writes

The transaction around a catalog write that has moved onto it.

`RunChanges` begins one transaction. The catalog pool has one connection, and the transaction holds it, so the closure and everything it calls must use that transaction rather than `Catalog.DB`. The closure writes the rows and returns them as `[]rowchange.Change`. On a non-empty list, `RunChanges` asks `effects.Resolve` once what those changes touch, records the audit revision with that set (`audit.Record` stores the scopes the set names), recomputes handles and reprojects search documents when those sets are non-empty, commits, runs `AfterCommit`, then notifies listeners with the `Commit` (`Result` is that type: revision, the time the revision was recorded, and the effects). A closure error rolls back and does not notify. An empty change list rolls back.

A change list whose every row names a table with effect `None` commits with no revision, no effects, and no listeners, then runs `AfterCommit`. `subject_position` and `file_derivative` are those rows. Thumbnail inserts return the derivative link and leave the derived `files` row off the list, so the batch takes this path; the Source search refresh stays in `AfterCommit`. A mixed list drops every `None` row before audit and effects. Those rows are already written, so they commit with the revision and are not recorded. A position returned beside an audited row is stored that way. The derived `files` row stays off the list: a file change is not `None`, and including it would audit the batch.

`RunChanges` returns the `Result`, the revision and the resolved effects; its closure returns only the changes. `Run` is `RunChanges` for a closure that also returns a value: the created or updated row. `Call` is `Run` with the revision discarded, for a test that only needs the written value.

A second `Run` on the same catalog, including from `AfterCommit` or a listener, returns `database.ErrWriteReentry`. `Run` does not take the catalog session lock.

Commit listeners implement `OnCommit` and `Drop`. The catalog graph registers one. If any `OnCommit` fails, `Notify` calls `Drop` on every listener and `Run` logs that error and still returns success: the write is already committed.

Property terms, the Source layer, the evidence layer, and the conclusion layer are the writes on `Run`: sources, notes, metadata, source types, metadata fields, artifacts, citations, observations, subjects, connect, positions, promote, identity claims, canonical entities, credibility assessments, property create, update, and delete, and a subject type's property bindings (assign, remove and reorder, audited as `subject_type_property`; they drop the cached vocabulary). The FFI handlers call `Run` or `RunChanges`. Those functions take `*database.Tx` and do not begin, commit, or record audit. `ingest.File` and `derivatives.Ensure` call `Run` themselves. A checksum conflict starts a second `Run` after the first returns. `artifacts.Delete` unlinks released objects from `AfterCommit`. A filename update returns a `file` change, and the registry refreshes the parent Source search document; a new file with no artifact resolves no Sources. The Source seed writes through `Run` too: `sourcetypes.UpsertTx` and `metadatafields.UpsertTx` return row changes, and `sourcevocab.Install(tx)` composes on the transaction `onboarding.createCatalog` opens (one `install_source_vocabulary` revision, no user). The subject vocabulary and the credibility grades seed the same way: `properties`, `propertyterms`, `subjecttypes` and `sourcecredibilitygrades` `UpsertTx` and `subjectvocab.EnsureBindingTx` return row changes, and each `Install(tx)` composes on a transaction `createCatalog` opens (`install_subject_vocabulary`, one revision; `install_source_credibility_grades`, none: its table is `None`). Name and date inserts stay on the observation's transaction. Summary dependents come from `catalog_search_inputs`. `GetDeleteImpact` reads through `deleteimpact.Snapshot`. A test fails on `.Begin()` outside `core/database` and `core/writes`.

The map of the schema packages is in [`catalogmodel`](../database/catalogmodel/README.md).
