# effects

What a change to one table touches after the row is written: the Evidence graphs whose loaded rows it moves, the keyed partial reads it moves per graph, the handles whose reconciled values must be rewritten, the search documents to reproject, and whether vocabulary labels or structure changed.

One `Effect` per table outside [`catalogmodel`](../catalogmodel)'s skip bucket. An empty field means that job is unaffected. `None` is an explicit empty entry (`users`, layout rows, grade tables).

Paths walk edges declared in `catalogmodel.FKs`: `up`, `across`, `inbound`, `from`, `field`, `self`, `chain`, `union`, `onField`, `onStatus`, `onDelete`, and `sql` for a walk those cannot say. Package init panics when a path names a missing edge. A column on the diff contributes its old and new ids. A column absent from the diff is read from the live row. A delete's old fields are used only when the row is already gone.

`Resolve` takes `[]rowchange.Change` and is the one walk of a batch: it returns `Set.SourceScopes` and `Set.HandleScopes` (the audit scopes), `Set.Deleted` (the ids a change deleted, by entity: `Effect.Deleted` is a path guarded by `onDelete` that ends at the entry's own table, reported under its `Entity`, so `canonical_entity` lists the handles and a merge, which updates a handle, is not listed; the app reads it from `WriteEffects.deleted`), `Set.EvidenceGraphs` (the Evidence graphs whose loaded rows a change moves: every registry entry keyed by graph drops each through `graphcache.DropNamedGraphs`: the loaded graphs, their records, layers and candidates), `Set.Reads` (the keyed partial reads a change moves, each with the key ids it moved them for), `Set.Handles` (the recompute set), search documents, `Set.Lists` and the structure flag.

A Subject that changes Source names its own handles, whose loaded members carry it. An Artifact that changes Source names no handle: every Subject citing it moves with it (`observations.requireSameGraph`), so the Subject's own change names the handles.

A write names only the graphs whose loaded rows it moves. A Subject, Observation or claim row names its Subject's graph. A Citation names the graphs of its Observations (`EvidenceGraph`), and so a Citation with none yet names no graph for the cache, while its `citations` read is the graph it was made in (`graph_id`); an Artifact's own fields move no loaded row, so an Artifact row names none (its Citations and Observations carry their own); a Citation's metadata value names the graphs of its Citation's Observations, as the Citation does, so a Citation's page shown in a loaded graph refreshes. A Source row names no graph: no loaded graph holds Source words, which live in the Source records entry (`sources.Records`), updated from the `source_records` read; a title edit still reprojects the Source's graphs' search documents (`DocEvidenceGraph`). Graph rows (`evidence_graphs`) name themselves; link rows (`evidence_graph_artifacts`) name no graph, since a cached graph holds no links.

`Set.Reads` is the shape of `Set.Search`: `Effect.Reads` is a list of `ReadPath{Read, Path}` where the path ends at the read's key table (`Read.KeyTable()`: Evidence graphs for `citations` and `evidence_graph_progress`, Sources for `evidence_graphs`, `inherited_values`, `source_holdings` and `source_records`, Properties for `property_terms`), and `Resolve` collects the ids per `Read`, in the order of `effects.Reads`. The reads are a closed vocabulary like `Lists`: `citations` (a graph's citation counts and citations by Artifact; moved by Citations, by their `graph_id`, Observations, and the value rows an Observation owns; a link row holds no Citation and moves none, and neither do a Citation's own metadata values) `inherited_values` (what the boards below a Source inherit: moved when the Source's metadata values change, so the shown Source page reloads and the cached Artifact and graph boards inherit the new value) `evidence_graph_progress` (a graph's Subject, filed and Observation counts; moved only by Subjects, Observations, Identity Claims and their evidence, so an Artifact edit or a Source title edit never refetches progress) `property_terms` (a Property's term list; moved by its terms, so a term write reloads only that Property's list) `source_holdings` (what a Source holds: moved when an Artifact or an Evidence graph joins or leaves it by create, delete or a move of its `source_id`, or when an Artifact's `file_id` changes; a label, description or graph-name write moves nothing; the Source page's workspace and the Sources list row follow it) and `source_records` (a Source's words: its row, its Artifacts, its credibility; moved only by those three tables, so an Observation or note edit never reloads a Source record). `Set.IDsOf(read)` is the lookup of a read's ids. A new keyed read is a `Read` constant, a `KeyTable` case, an entry in `Reads` and `Reads:` on the registry entries that move it; the wire key is the constant's value (`WriteEffects.reads`) and Swift's `CatalogRead` mirrors it, with a `refresh` entry on the descriptors that cache it.

`Set.Lists` holds the catalog-wide lists the batch changed, each once, in the order of `effects.Lists` (`Set.Has(l)` tests one): `source_vocabulary` (a Source type or a metadata field changed), `property_vocabulary` (a subject type, Property, Property term or binding changed), `property_usage` (an Observation was created, deleted, or moved to another Property: `Effect.ListsOnField` narrows an update to the ones that write `property_id`), `metadata_field_usage` (a Source, Artifact, Evidence graph or Citation value was created or deleted: those entries set `ListsOnCreateDelete`) and `counts` (a Source or a handle of any type was created, deleted or merged, so a sidebar count may have changed: `sources` sets `Effect.ListsOnCreateDelete`, so an update never moves it, and `canonical_entities` narrows an update to a write of `merged_into_id`). Which updates move `Lists` is one choice per entry: all, those writing `ListsOnField`, or none (`ListsOnCreateDelete`). A new catalog-wide list is a `List` constant, an entry in `Lists` and `Lists:` on the registry entries that move it; the wire key is the constant's value (`WriteEffects.lists`) and Swift's `CatalogList` mirrors it. `Effect.HandleScope` is the handles whose last activity a change moves; `Handles` is wider. `Effect.SourceScope` is the Source whose last activity a change moves, and `Effect.EvidenceGraph` is the Evidence graph whose loaded rows changed (a path that ends at `evidence_graphs`), so a note, credibility, or file write, or a metadata write other than a Citation's value, moves activity and drops no cached Evidence graph. [`writes.Run`](../../writes) calls `Resolve` once, hands the `Set` to `audit.Record`, then recomputes handles and reprojects search when those sets are non-empty. Each scope path is walked once per write. `Run` sets `Set.SummaryDeps` from the [input index](../../../docs/deployment-plan/archive/spike-14/summary-inputs.md) (`searchindex.ReprojectChanged`).

`Scopes` (`scopes.go`) declares every audit scope type once: its name and which ids of a `Set` belong to it (`source` from `SourceScopes`, `canonical_entity` from `HandleScopes`). The Source records entry (`sources.Records`) and the app's page inputs read the `source_records` read, which `sources`, `artifacts` and `source_credibility_assessments` set; a table the Source record gains (S15-05's `date_values`) adds its `source_records` path. Those tables keep their `SourceScope` paths for the audit. The graph index (`evidencegraphs.Index`) reads `Set.Reads` too: it re-lists the Sources under `evidence_graphs` and recounts the graphs under `evidence_graph_progress`, so `subjects`, `observations`, `identity_claims`, `evidence_graphs` and `evidence_graph_artifacts` must keep those `Reads:` paths. `audit.Record` stores one `audit_transaction_scopes` row per id of each `Scopes` entry, and the display cache ([`graphcache`](../graphcache)) keeps each type's last activity current from the same ids. A new scope type is one `Scopes` entry. `Commit` (`commit.go`) is a landed write: its revision, the time that revision was recorded, and its `Set`. It lives here because the display cache accepts it and `core/database`, which imports the cache, hands it to listeners. This package does not import `audit` or [`deleteimpact`](../deleteimpact).

The metadata tables' entries (`Entity`, `SourceScope`, and the field list moved by a value) are built from `catalogmodel.MetadataTables` by `metadataEffects`; only extras such as `Search` are a partial literal in `registry`.

`registry_completeness_test.go` checks that every non-skip table has an entry and that a cascade into a table with effects is audited. `handle_paths_test.go` checks membership, trigger columns, claim status, and date values. Source parity runs beside `audit.TestSourceScopes`.

The map of the schema packages is in [`catalogmodel`](../catalogmodel/README.md).
