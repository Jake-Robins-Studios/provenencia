# Deployment plan — Spike 15

Spike 15 makes Sources carry what a standard genealogical citation needs and turns it into citations. It pulls in every design doc in this folder: the Source date ([`source-provenance-date.md`](source-provenance-date.md)), citation formats and the seed ([`evidence-explained-citation-map.md`](evidence-explained-citation-map.md), which supersedes the arrival steps of [`citation-formats.md`](citation-formats.md)), moving an Artifact ([`move-artifact-between-sources.md`](move-artifact-between-sources.md)), the privacy toggle ([`2026-10-27-source-privacy-toggle.md`](2026-10-27-source-privacy-toggle.md)), the credibility field ([`2026-10-18-credibility-field-truncates-and-ignores-enter.md`](2026-10-18-credibility-field-truncates-and-ignores-enter.md)) and the metadata rethink ([`2026-10-25-rethink-source-metadata-and-type-suggestions.md`](2026-10-25-rethink-source-metadata-and-type-suggestions.md), settled: metadata stays). One behavior, one PR.

**One brief, one PR.** A PR that adds, changes or removes chrome waits on its own brief; a removal is gated too. A brief gates exactly one PR, and draws only what that PR ships; a later PR on the same view gets its own brief (user, 2026-11-13). Briefs and PR plans are written just before the PR ([`add-design-brief`](../../../.agents/skills/add-design-brief/SKILL.md), [`plan-pr`](../../../.agents/skills/plan-pr/SKILL.md)). Only a PR whose views look the same before and after is not gated. S15-D1 and S15-D14 were written before this rule and gate several PRs; they stay as written.

## Status

> **Goal of this spike:** a researcher gets a correct, editable *Evidence Explained*-style citation for any Citation from data entered once on the Source, the Artifact, the Evidence graph or the Citation, and can re-file Artifacts between Sources.

## Goal (dogfood bar)

**By spike close**, each of these is true on a real project:

1. **A Source has a date.** Set, change and clear it on the Source page with the app's date entry. The Sources list shows it on each row and sorts by it, undated last. The Person page's Sources section shows it on each Source.
2. **A Source can be marked not public.** A switch on the Source page; it is saved and survives reopening. Nothing else changes yet.
3. **Copy and item details live where they belong.** On a census Source, the Artifact holds provider, URL and accessed date (also offered when the Artifact is added), and each household's Evidence graph holds dwelling, family and line. The citation composer gains the printed page; from slice 11 it holds the Citation's own fields (bar 13).
4. **Citations read like citations.** A census Citation's provenance sheet reads "1880 U.S. census, Ottawa County, Kansas, population schedule, ED 236, p. 14, dwelling 112, family 118, Ada Robins; digital image, *Ancestry* (… : accessed 12 March 2025)". Copy citation gives the full or short form. Each metadata board flags the fields its type's citation needs and are empty (the census Source: "Jurisdiction, needed for citation"; user, 2026-11-19: the seed puts every Artifact and graph field in an optional group); the Source page copies its source-list entry.
5. **Formats are the researcher's.** Editing the Census format (on the type's page until slice 12, then on the format's own page) updates a live preview against a real Source. **Copy** on a type's page starts a new type with the parts the researcher ticks, its suggestions among them.
6. **A new project knows the citation styles.** It starts with the 26 seeded types, the seeded fields (map § 6.8's 63, plus the place fields of 2026-11-21 and slice 11's `page`), each type's suggested fields and, from slice 12, 23 seeded formats. The product owner updates the dogfood projects by hand (user, 2026-11-17).
7. **One household, one citation.** The five Citations drawn on one household row show as one citation, with the highlighted pieces beneath it, on the provenance sheet. The Person page's Sources section does not show citations (user, 2026-11-21: citations belong to an Observation, so a researcher reads them on the provenance sheet; the Sources section stays a list of the Sources behind the person).
8. **An Artifact moves with its graphs.** **Move to another Source…** from an Artifact or a graph shows everything that moves together, keeps every ref, and the moved Citations then read the target Source.
10. **A heavy provenance sheet stays quick.** Person, Event and Place rows all open the same provenance sheet (the Why accordion is gone); a page loads without any record behind its values; a value's records arrive when its sheet opens, with a loading state and a Try again on failure; a value with 1,200 records opens on a page of rows with Show more.
9. **The credibility argument behaves like a text area.** A long argument wraps, and it saves with the Save button, like the Source description.
11. **A researcher can say a value is unknown or supplied.** A book Source with no place of publication marked unknown cites "n.p."; an undated letter dated from its postmark cites "[12 March 1880]"; marked-unknown values are no longer flagged as needed. A date in a citation reads "ca. 1880", where the app's pages read "abt 1880".
12. **A board reorders without a mouse.** On any metadata board (the Source's Metadata section, the Artifact sheet, the graph form), a saved row's handle takes focus with Tab and moves with ⌥↑ / ⌥↓, and focus stays on it. With VoiceOver on, "Move down" on the first saved row makes it second and announces "Provider, 2 of 3". The order survives a reload.
13. **A Citation holds its own details.** In the composer, a newspaper Citation takes its printed page and column, and cites "p. 2, col. 4". Five Citations on one clipping can instead take them once from their graph or Artifact. In a whole-issue PDF, two Citations of one graph cite "p. 2, col. 4" and "p. 7, col. 1". A census Citation reads its line, dwelling and family the same way (user, 2026-11-22).
14. **A value is entered once, at whichever level fits.** A format names a field, never a level: a census Source whose provider was typed on the Source cites it exactly as one typed on the Artifact. A Source type lists its suggested fields once, and every board (Source, Artifact, graph, Citation) offers them. A board shows the value a field inherits and where it comes from ("From graph: 4"); typing a value overrides it for that one owner, and clearing it falls back. A field the source-list entry needs, typed on an Artifact and not on the Source, is flagged with **Move to Source** (user, 2026-11-22).
15. **A type says what a record is; a format says how it is cited.** A researcher's Obituary type cites with the Newspaper item format. The three civil certificates share one Certificate format, so one edit changes all three, and a birth certificate's note reads "Ohio, Birth certificate no. 123". A Source can use a format other than its type's default. A format opens on its own page, which says how many types and Sources use it (user, 2026-11-22).

**Scale** (user, 2026-11-09). A census Source with **60 household graphs of 1 to 10 Citations each** (600 Citations); a Person page citing **30 Sources**, so a provenance sheet or Sources section renders up to **300 citations**; a move bundle of **5 Artifacts and 5 graphs**; up to **1,200 records on one value** (a crafted project, or a Place's name row; [`provenance-loading.md`](provenance-loading.md)); the seed's **26 types and 69 fields**. Also: a project of **3,000 Sources** (Spike 16's Scale) for the Sources list; a Source with up to **60 Artifacts**; a move bundle's graphs holding up to **100 Subjects** in all; a format or field edit on a type used by **500 Sources**; a Citation's board of up to **8 page-relative fields**, and a render of 300 Citations reading their Citation values in one batched read (slice 11); a board showing up to **30 suggested fields**, each with the value it inherits, read with its owner's ancestors in one batched read; one format shared by **3 types and 500 Sources**, and a format picker over about **25 formats** (slice 12). Plans write their fan-out against these.

## Working rules

These are the calls for this spike. PR plans treat them as binding.

- **Follow the *Evidence Explained* style; never copy the book.** Seeded formats, examples, tests, fixtures and UI copy are written for Provenencia; every example uses invented people, places and records; no product or feature name uses the book's name; nothing is called official. The full rule: [`README.md`](README.md#working-rules). Binds S15-14, S15-19 and every PR with copy.
- **The Source date is one optional DateValue on `sources`.** `sources.date_value_id` into `date_values` ([`add-date-value`](../../../.agents/skills/add-date-value/SKILL.md)); its meaning is the original publication, or when the record was made; no backfill. Copy Source carries it only when the Copy form's Published date tick is on (S15-32; user, 2026-11-09). The Sources list sorts by it, undated last. Metadata dates stay text. Binds S15-02 – S15-05. Design: [`source-provenance-date.md`](source-provenance-date.md).
- **Not public is a stored switch and nothing else.** `sources.is_public INTEGER NOT NULL DEFAULT 1`, toggled on the Source page by a switch labeled "Private", off by default (user, 2026-11-09). No filtering, hiding, list glyph or cascade. Copy Source carried it from neither (user, 2026-11-09) until Spike 16's S16-74, where the Copy sheet's Private switch starts as the original's (user, 2026-11-26). Binds S15-02, S15-03. Design: [`2026-10-27-source-privacy-toggle.md`](2026-10-27-source-privacy-toggle.md).
- **Metadata lives at four levels with one vocabulary.** The Source (the record), the Artifact (the copy used), the Evidence graph (the researcher's grouping) and, from S15-54, the Citation (the spot cited; user, 2026-11-22) each hold values and layout, with the same fields from `source_metadata_fields`, which keeps its name. Tables: `artifact_metadata`, `artifact_metadata_layout`, `evidence_graph_metadata`, `evidence_graph_metadata_layout`, `citation_metadata`, `citation_metadata_layout`. Layout rules (order, dismiss) are the Source's at every level. Binds S15-07 – S15-12, S15-54. Design: map § 6.6; rule "A Citation holds metadata".
- **One level type.** Source, Artifact, graph and Citation are one Go `Level` type in the pure package `core/vocabkey`, used by suggestion rows, metadata owners, the format prefixes and the built-ins table, and the RPCs. All four hold metadata (the first three before S15-54), so `vocabkey.Levels()` is the set and owners and the suggestion table's `CHECK` use it, with no separate list of metadata levels (user, 2026-11-24, superseding S15-54's `MetadataLevels()`); the Citation level also has built-ins. Swift mirrors the type as one enum `Level`, with a row in `api/ffi/swift_vocabulary_test.go` (user, 2026-11-11). S15-06 adds it; S15-14 uses it. (K-6, K-20.) From S15-62 a format's metadata placeholders take no level, and from S15-63 suggestion rows take none; the type stays for owners, built-ins and the resolution order.
- **Metadata saves with its owner's write.** Values entered while adding or editing an Artifact, or saving the Evidence graph form, go in the same transaction as the Artifact or graph (`CreateArtifactRequest`, `UpdateArtifactRequest` from S15-33, the graph create and update requests). Drafts save through one `sourcemetadata.Apply(tx, owner, draft)`, which compares the draft with what is stored and runs the steps `Set`, `Clear`, `DismissSuggestion` and `Reorder` use; `CreateAll` becomes its empty-owner case. Live boards save per field, as the Source page does; since S15-34 the Source's own board is the only live one (user, 2026-11-12). (K-1, K-19.) Binds S15-08, S15-10, S15-11, S15-33, S15-34. (K-1.)
- **One metadata board.** The Swift board model and view take an owner (kind, id, its entries and its write operations); the Source page, the Artifact sheet (add and edit), and the graph form all use it. Binds S15-26, S15-09 – S15-11, S15-34. (K-2.)
- **An Artifact is added and edited in one sheet.** The Artifact sheet holds the label, the description, the Evidence graphs it is in and its copy details (the board on a draft, with the type's `artifact`-level suggestions); nothing saves until Save, and Cancel discards. Editing saves in one `UpdateArtifact` write with the draft; adding is one `CreateArtifact` write with the draft, then the file's ingest as its own write, as today. Both replies carry the Artifact's saved rows, so the page patches its cached workspace (`.wroteMetadataBoard`) instead of reloading. Editing on the card goes; the list shows each Artifact's saved copy details read-only, more tightly than a form, with a square thumbnail tile of at most 80pt: a square crop fills from the short edge (about 170 pixels of the engine's 256-pixel thumbnail on a census page), so 80pt is the largest that stays sharp at 2x; no derivative size changes (user: "just display a smaller thumbnail"). Rows or compact cards is the board's call (user, 2026-11-12). Replaces S15-D1 SD-9 and SD-10 and folds S15-D4 into S15-D14. Binds S15-33 – S15-36, S15-10, S15-25.
- **A board adds a field in an inline row.** Add field on every metadata board, the Source's own included, is an inline row in the board (pick a field, type a value), not the Add metadata dialog, which goes (user, 2026-11-12). On the Source's own Metadata section only the header's Add field opens the row; there is no second button at its foot (user, 2026-11-13). On a live board the row saves at once; on a draft it adds to the draft. A draft board clears a row with no confirm (Cancel restores it). Binds S15-34, S15-36, S15-11.
- **One window; nothing is built for a second.** The app opens one workspace window (Spike 16's S16-62; user, 2026-11-18), and no plan, brief or review asks what another window does meanwhile. Forms open from the page's values with no fresh read (user, 2026-11-14). What one window still meets stays handled: Back to a place whose entity was deleted or merged, and a write's effects on other places' caches. Replaces "No engineering for two windows editing the same data" (2026-11-14); Spike 16's rule "(Batch 7) Nothing is built for a second window" holds the details. Binds S15-11 and every later form.
- **One date order.** The rule for where a date sits in an order (today the private `datePlace`, `dateKeyOf` and `dateKeyLess` in `conclusionsummaries`) moves to `core/valuecompare` beside `DateEnds` as an exported key and comparison, which `conclusionsummaries` and `sources` both call; it gives each Source a date sort key on the wire; Swift's Sources list sorts by that key, undated last, and never orders dates itself. Binds S15-02, S15-04. (K-12.)
- **Suggestions have a level.** `source_type_metadata_fields.level` is `source`, `artifact` or `graph`, in the table's key. An Artifact's and a graph's suggestions are their Source's type's rows at that level. Binds S15-06, S15-09 – S15-12, S15-19. **Superseded (user, 2026-11-22)** by rule "A type suggests fields, not levels" (S15-63).
- **The item is a graph field.** What a graph is about ("Ada Robins", "baptism of Ada Smith, 3 March 1830") is the seeded graph-level field `item`, typed once per graph and read as `{graph.meta.item|source.meta.item}` (as `{meta.item}` from S15-62); nothing derives it from a Citation's Subjects, and no Subject is marked as the graph's principal (parked in [`ideas/evidence-graph-followups.md`](../../ideas/evidence-graph-followups.md) "Primary subject") (user, 2026-11-09). Binds S15-16, S15-19. Design: map § 6.5. The page-relative item fields are not graph fields (rule "A format reads a field from the nearest level that holds it").
- **Citations carry no metadata.** The composer's only new input is the printed page (`page_label` on the `page` selector, already in the locator). Binds S15-13. Design: map § 6.9. **Superseded (user, 2026-11-22)** by the four rules below, slice 11; S15-13 shipped under it, and S15-58 and S15-59 retire its locator part.
- **A Citation holds metadata (user, 2026-11-22).** The Citation is the fourth metadata level: `citation_metadata` and `citation_metadata_layout`, with the same fields from `source_metadata_fields` and the same layout, marks and audit as the other three. `vocabkey.Levels()` has `LevelCitation` (rule "One level type"), so the Citation's board offers its type's suggestions like every other (rule "A type suggests fields, not levels") and `{meta.key}` reads it first. A Citation's values save with its write: `CreateCitationWithObservations` and `UpdateCitation` take a `MetadataDraft` (rule "Metadata saves with its owner's write"). Deleting a Citation releases its values, and every delete that removes Citations (the Citation's own and its graph's; an Artifact or a Source holding Citations cannot be deleted) releases theirs through the same path ([`add-catalog-delete`](../../../.agents/skills/add-catalog-delete/SKILL.md)). Its audit scope resolves through the Citation's Artifact to that Artifact's Source, so a moved Artifact's Citation values follow it with no change to the move (S15-24). No search document is built from Citation values, as for Artifacts and graphs. **Refused:** moving a Citation to another Artifact; a Citation is bound to its Artifact (user, 2026-11-22). Binds S15-54 – S15-61.
- **The printed page is a metadata field.** The seeded text field `page` ("Page", unknown text "unpaginated") replaces the `{citation.page}` built-in and its requirement; its unknown and supplied facts are the metadata marks. `{citation.image}` (the file page) stays a built-in. Outside a rendered citation, a reader shows only the Citation's own `page` value, or none, and the file page: the Conclusion detail through `graphfill` and `conclusiondetails`, `CitationLineDisplay`'s fallback line, the likeness and depiction viewers. Nothing resolves the inherited page except a format render, so no reader of its own walks the levels and no cache holds an inherited value (rules "A format reads a field from the nearest level that holds it", "Citations render on demand, from SQL"); a reader that needs the inherited page asks the render RPC. `graphfill` reads the Citation's own value, so S15-54 declares `citation_metadata`'s effects path to its Evidence graph (map review K-1). The field is found one way: its key is declared once in `core/vocabkey` and resolved through `metadatafields.ResolveKeysTx` preferring the seed's origin, and the values are read through `sourcemetadata.ListByOwnersTx` (which settles the marks), never by SQL of the reader's own. A project without the field shows no printed page. A page marked unknown shows the field's unknown text, and a supplied one shows in square brackets, as a citation prints them (map review K11-12). Binds S15-56, S15-58.
- **The locator only finds things in its Artifact.** Its page selector holds the file page (`artifact_page`) and nothing else: `page_label`, `page_unknown`, `page_supplied` and the label-only page selector go, with S15-44's locator marks. Stored locators are not migrated (user, 2026-11-22: one dogfood graph has printed pages and is fixed by hand; no depiction has one): reads ignore those keys, no read fails on them, and the next save of that Citation writes them out. Depiction regions compare file pages, as today. Binds S15-59.
- **Page-relative fields are read from the Citation first.** **Superseded (user, 2026-11-22, later)** by rule "A format reads a field from the nearest level that holds it", which reads every field this way, so no seed helper writes a chain; S15-60 is re-scoped. Kept for the record: a seeded field whose value is a position on a printed page is suggested at the Citation level and read through the chain `{citation.meta.key|graph.meta.key|artifact.meta.key|source.meta.key}`, most specific first (user, 2026-11-22). A researcher sets it once at the level that fits how they filed: a clipping's five Citations take page and column from their graph or Artifact; a whole-issue PDF's Citations each carry their own. The page-relative fields: `page`, `column`, `line_number`, `dwelling_number`, `family_number`, `schedule_number`, `entry_number`, `folio`. `item` and `record_id` keep `{graph.meta.key|source.meta.key}` (rule "The item is a graph field"). An Evidence graph is the researcher's grouping of evidence, which may span pages and Artifacts, not an item (user, 2026-11-22), so map § 6.9's "the item lives on the Evidence graph" no longer holds for these fields; S15-60 writes the chain once through a helper in the seed registry and rewrites § 6.9 and `docs/seeded-vocabulary.md`. Binds S15-55, S15-56, S15-60.
- **A format reads a field from the nearest level that holds it (user, 2026-11-22).** A metadata placeholder is `{meta.key}`, with no level, and resolves at the Citation, then its Evidence graph, then its Artifact, then the Source, the first that holds a value. The graph and the Artifact are parallel branches that meet at the Source (a Citation's graph is linked to its Artifact, and `Link` refuses another Source's Artifact), so "graph before Artifact" is a fixed tie-break, not a claim that one is inside the other. A value marked unknown at a nearer level answers and stops the search, as an unknown option stops a chain today. The list form reads the Source alone, so `{meta.key}` there resolves at the Source only. `{a|b}` stays, now between fields or built-ins (`{meta.short_title|source.title}`). Built-ins keep their level (`{source.title}`, `{source.date:year}`, `{citation.image}`). A level-named metadata placeholder (`{source.meta.key}`) is a parse diagnostic, `meta_at_level`; `unprefixed_meta` goes. No migration rewrites stored formats (no users; the dogfood project is rewritten by hand, user 2026-11-22); a chain whose options become the same field reads as that field once. The order is `vocabkey.Levels()` reversed (`NearestFirst()` is `Levels()` reversed with `slices.Reverse`, so it is declared nowhere else); S15-61's level list gives each entry ordered parents (`Ups`: the Citation's graph, then its Artifact, the Artifact marked as the audit-scope path; S15-54), and a parity test checks only that each entry's `Ups` agree with `NearestFirst`. `core/citationformat` parses `{meta.key}` and never walks levels. One walker walks them, `sourcemetadata.CitationValues.Nearest`, which boards and renders already share through `Resolve`: the render, the board's "met above" and the inherited value (S15-64: `Nearest` on the values `Without` the owner's level) all go through it, and nothing else walks the levels. Binds S15-62, S15-54, S15-55, S15-60, S15-64. Updates [`docs/citation-formats.md`](../../citation-formats.md) and map §§ 6.3, 6.6, 6.9.
- **A field means one thing.** When one format would want a field's value from two levels at once, the two values are two fields. The seed has no such case: `url` and `accessed_date` stay one field each (where the record was viewed, the copy's for most types and the page's for `website`), read nearest-first like every field, and no `copy_url` is added (user, 2026-11-22, confirmed). A field is added only when a format needs to print both. Binds S15-62, S15-72.
- **A type suggests fields, not levels (user, 2026-11-22).** `source_type_metadata_fields` loses `level`; a type's suggestions are one ordered list, and every board, at every level, offers all of them. S15-63's migration changes the schema only and carries no rows; the product owner's one dogfood project gets its suggestions back from a one-time script after S15-63 lands (user, 2026-11-23). The type page shows one Suggested fields list, and Copy type one suggestions tick. The seed declares one list per type (`registry_suggestions.go`), and `TestSeedSuggestionsFollowFormats` derives it from the type's formats in first-read order. Binds S15-63, S15-54, S15-72. Updates [`docs/source-layer-data-model.md`](../../source-layer-data-model.md) § 5.2 and [`docs/seeded-vocabulary.md`](../../seeded-vocabulary.md) § 2.3.
- **A board shows what its owner inherits.** Each board entry carries, besides its own value, the value it inherits from the nearest level above that holds one, with that level and its mark (an Artifact's and a graph's from the Source; a Citation's from its graph, else its Artifact, else its Source). The row shows it read-only with where it comes from; typing a value overrides it for this owner only; clearing falls back. Ancestors' values come from the one batched read S15-55 adds, never a read per row. Showing values below an owner (a Source's Citations) is not built. Hiding inherited rows behind a control is a later choice, made once the boards are in use (user, 2026-11-22). Binds S15-55, S15-64, S15-56.

### Slice 10 — Keyboard reorder

#### S15-51 — Board rows reorder by keyboard and VoiceOver

**Ships.** In the kit: `PVReorderHandle` takes focus. With it focused, ⌥↑ / ⌥↓ moves its row by one, and focus stays on the moved row's handle. Fan-out: one reorder write per move on a live board of a few dozen rows; none on a draft board.
